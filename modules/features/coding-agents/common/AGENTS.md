# Code Documentation Guidelines

- Default to no comment. A comment survives only for a why-not (the alternative a reader would reach for, and its non-obvious failure) or an invariant the code cannot show; never for WHAT the code does, and never for history
- A why that only justifies the current change goes in the commit body, not the source
- Test code should clearly describe WHAT is being tested
- Commit messages must include WHY the change was made

# Language Requirements

- All documentation, comments, and commit messages must be written in English
